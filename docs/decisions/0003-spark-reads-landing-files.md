# 0003. Spark 는 착지(landing) 파일을 읽고, 결과만 ClickHouse 에 넣는다

- 상태: 채택
- 날짜: 2026-09-23

## 배경
세션 지표와 일별 지표는 이벤트 전체를 훑어야 한다. 이런 집계를 어디서 할지 두 가지 선택지가 있었다.

1. ClickHouse 안에서 SQL 로 집계
2. Spark 가 읽어서 집계하고, 결과만 ClickHouse 에 적재

## 결정
Spark 가 **JSONL 착지 파일**을 읽어 집계하고, 결과를 ClickHouse 마트 테이블에 넣는다.
Spark 는 Docker 이미지(`apache/spark`)로 실행한다. 로컬에 Java 를 설치하지 않는다.

## 이유
- 운영에서는 원본 로그가 오브젝트 스토리지(S3 등)에 쌓이고 Spark 가 그것을 읽는 구조가 흔하다.
  여기서는 로컬 파일이 그 자리를 대신한다. 나중에 경로만 바꾸면 같은 코드가 동작한다.
- 세션 묶기, 검색 간격의 표준편차처럼 행 사이 관계를 다루는 계산은 Spark 쪽이 표현하기 편하다.
- ClickHouse 는 조회를 맡는다. 대시보드와 이상 탐지는 마트 테이블만 보면 된다.
- Spark 를 Docker 로 돌리면 Java 버전 문제를 피할 수 있고, 다른 PC 에서도 같은 결과가 나온다.

## 감수하는 것
- Spark 가 ClickHouse 를 직접 읽지 않으므로, 적재 이후 원천에 들어온 이벤트는 다음 배치에서 반영된다.
  (ClickHouse 를 직접 읽으려면 JDBC 드라이버를 내려받아야 해서 실행 조건이 늘어난다)
- 결과를 JSONL 로 주고받는다. Parquet 보다 크지만, 적재기가 표준 라이브러리만으로 읽을 수 있다.

## 멱등성
마트 테이블은 `ReplacingMergeTree` 다. 같은 배치를 다시 적재해도 키가 같으면 최신 것만 남는다.
단, 병합 전에는 예전 행이 남아 있을 수 있어 조회할 때 `FINAL` 을 붙이거나 집계로 중복을 흡수해야 한다.
